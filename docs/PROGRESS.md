## Фаза 3 — авторизация ✅
Закоммичена (см. `git log`).
- `api/`: `client_id` берётся со страницы soundcloud.com (`__sc_hydration` → `apiClient`). Запрос `/me` идёт с `Authorization: OAuth`. На 401/403 `client_id` обновляется один раз, на 429/5xx запрос повторяется с backoff. Модель `Me`.
- `auth/mod.rs`: сессия, токен в Credential Manager, кэш профиля в `session.json`. На старте `/me` проверяется в фоне. Разлогин только при 401 на `/me`. `auth_logout` стирает токен, профиль WebView не трогает.
- `auth/login.rs`: окно `login` на `https://soundcloud.com/signin` с постоянным профилем `%APPDATA%\dev.eidetism.scdesktop\login-profile`.
  - Без подмены UA, без JS-инъекций и автозаполнения.
  - Раз в секунду ищется cookie `oauth_token` → проверка `/me` → вход → окно уничтожается.
  - Через нативный WebView2 (`webview2-com`) читается UA и ловится `FrameNavigationStarting` на `captcha-delivery.com`. Тогда показывается окно-плашка `login-hint` (`index.html?view=captcha-hint`).
- `auth/browser_proxy.rs`: флаги прокси для WebView2. Direct → `--no-proxy-server`, прокси без логина → `--proxy-server`.
- `auth/forwarder.rs`: локальный SOCKS5 на `127.0.0.1` для прокси с логином (SOCKS5 / HTTP CONNECT / HTTPS CONNECT).
- `app/navigation.rs`: окну `login` разрешена любая https-навигация.
- Фронт: гейт «без сессии только экран входа» (`src/auth/*`), «Привет, {имя}», «Выйти».
- Новые зависимости: `webview2-com`, `windows` (версии как у Tauri), `tokio-rustls`, `rustls-platform-verifier`, `base64`, у `reqwest` добавлена фича `query`.

### Правки после проверки фазы 4
- «Назад» идёт по истории реально сыгранных треков (до 200), а не по порядку очереди. Раньше при включённом перемешивании он уводил на случайный трек. Как и раньше, после 3 с «назад» перематывает трек в начало.
- Качество: первым пробуется `aac_256k` (Go+), при отказе — `aac_160k`, затем `aac_96k`. Вживую у пользователя (Go+) 256k отдаётся.
- Кнопки плеера — иконки `lucide-react` (новая зависимость: иконки из стека CLAUDE.md).
- **Треки с DRM** (не только Go+: в основном бесплатные треки мейджоров `AD_SUPPORTED`; у пользователя 23 из 142 лайков, 16%): Widevine/PlayReady через BuyDRM KeyOS. Расшифровка в Rust — обход DRM, не делаем. Законный путь — играть только их через лицензированный CDM WebView2 (EME). Пробник показал: WebView2 на машине пользователя поддерживает Widevine и PlayReady (вкл. SL3000). **Решение пользователя: делать после UI (после фазы 6).** Понадобится HAR воспроизведения DRM-трека из Edge/Chrome (запрос к лицензионному серверу) и правка инвариантов в CLAUDE.md (звук и сеть этих треков — из WebView).

## DRM-треки через WebView2 ✅
По `docs/har/drm.har` (Firefox, трек `301967571`): обмен `ctr-encrypted-hls` → `{url, licenseAuthToken}`, плейлист CENC с ключами Widevine и PlayReady, лицензия — два POST (сертификат 2 Б, запрос ~5 КБ) на `license.media-streaming.soundcloud.cloud/playback/widevine?license_token=<licenseAuthToken>`, CORS `*`.
- Решение пользователя: вся сеть DRM — через Rust. Правила записаны в CLAUDE.md (раздел «Скрытое окно `drm`»).
- `player/stream.rs`: если обычного потока нет, берётся CENC (`aac_256k` → `aac_160k` → `aac_96k`), сегменты качаются зашифрованными с длительностями (`hls::download_segments`). CBCS не используется. `Access` считает CENC доступным — такие треки больше не серые.
- `player/drm.rs`: скрытое окно `drm` с нашей страницей `src/drm/player.ts` (MSE + EME Widevine, держит ~60 с буфера, перемотка по сегментам), профиль `drm-profile`, `--autoplay-policy=no-user-gesture-required`. Команды `drm_boot/segment/license/report` только от этого окна. Лицензия пересылается общим клиентом, ответ отдаётся CDM без разбора. Окно закрывается через минуту после того, как DRM-трек перестал быть текущим.
- Актор: play/pause/seek/громкость/позиция/конец трека идут в rodio или в окно `drm`; `audio:tick` для DRM шлёт Rust по отчётам страницы.
- Новые токены не нужны; capability `capabilities/drm.json` (`core:event:default`), CSP `media-src` + `blob:`.
- Проверено агентом вживую (release, UI Automation, звук на нуле): DRM-трек `1934849951` — сертификат и лицензия получены (2 Б → 710 Б, 4265 Б → 619 Б), время идёт 0:01 → 0:17. В самом первом запуске профиля `drm-profile` воспроизведение стояло — вероятно, WebView2 докачивал модуль Widevine; дальше работало.
- Не проверено вживую: перемотка и пауза DRM-трека, переход DRM → обычный трек и обратно, долгие треки (> 10 мин), работа в трее, прокси.
- Ограничения: у DRM-треков нет нормализации громкости и declick; пока играет DRM-трек, живёт отдельный процесс WebView2 (+40–60 МБ).
- В лог пишутся этапы DRM (`[player] … plays via DRM`, `[drm] …`).
- **Исправление 7 ноября 2026 (баг громкости).** DRM-трек не запускался у пользователя: актёр передавал в `drm::load` громкость в процентах (0–100), а страница ставила её как `audio.volume` (ждёт 0–1) и падала с `RangeError` ещё до первого этапа — отсюда тишина при любой громкости, кроме 0/1. `drm::load` теперь переводит проценты в уровень (как `set_volume`), страница дополнительно клампит `audio.volume` в [0,1]. Проверено вживую: `крип` играет при обычной громкости, все этапы и лицензия проходят.
- Диагностика DRM в логе (на будущее): версия страницы (`page ready (v2)`), строки `[drm] diag:` (возможности MediaSource/EME/Widevine, пойманные ошибки страницы через `drm_diag`), этапы запуска. Сторож: нет звука за 25 с → пауза с ошибкой `drm` и кнопкой «открыть в браузере»; если Widevine не ответил (15 с) или страница не прошла ни одного этапа — профиль `drm-profile` пересоздаётся при следующем «Играть». Адрес страницы получает метку запуска, чтобы WebView2 не брал старую из кеша.

Поэтому агент не видит лог, настройки и `session.json` из запусков пользователя, а пользователь не видит файлы агента. Credential Manager не виртуализируется и общий. Мнимый «баг логирования из Проводника» объясняется именно этим, бага нет.
