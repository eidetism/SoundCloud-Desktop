# SoundCloud Desktop (fork) — инструкции для агента

Личный десктоп-клиент SoundCloud **только под Windows 11**. Форк `zxcloli666/SoundCloud-Desktop` (MIT); `LICENSE` и копирайт автора не трогаем.
Подробный план и инвентаризация — `docs/FORK_PLAN.md`. Работа идёт по фазам: после каждой фазы — отчёт и ожидание «дальше», коммит на фазу (сообщения на английском), ветка `main`.

## Стек
Tauri 2 (Rust, edition 2024, toolchain из `rust-toolchain.toml`) + React 19 + TS + Vite + Tailwind 4 + zustand + TanStack Query/Virtual, lucide-react, i18next (ru/en, язык из системы), шрифт Inter (`@fontsource/inter`).
Identifier: `dev.eidetism.scdesktop`.

## Архитектура (инварианты)
- **Rust владеет состоянием и сетью**: сессия, очередь, текущий трек, позиция, громкость, кэш, настройки прокси. Фронт тонкий — рендерит и шлёт команды; Rust шлёт события.
- **Один HTTP-клиент** `reqwest` (`socks`, `rustls-tls`, `gzip`, `brotli`, `http2`), собирается из настроек сети (Direct / SOCKS5 `socks5h://` / HTTP(S) с логином), пересоздаётся при смене режима. Через него — API, аудио, картинки. Никаких других клиентов.
- **Хосты только SoundCloud**: `api-v2.soundcloud.com`, `soundcloud.com`, `*.sndcdn.com` (+ CDN HLS, если подтвердится по HAR). Ни одного запроса к серверам автора (`scnative`, `getsoundcloud`). `grep -ri scnative` должен быть пуст.
- **Картинки** — только через протокол `scimg://` (дисковый LRU, суффиксы `-t200x200`/`-t500x500`), никогда прямым `<img src="https://…sndcdn…">`.
- **api-v2 недокументирован** — эндпоинты и модели только по HAR из `docs/har/` (сырые HAR в git не коммитим). Неясна структура — остановиться и попросить HAR.
- **Стрим**: `media.transcodings` → progressive MP3, иначе HLS. Go+ без подписки — 30-с превью или «недоступно», не обходить.

## Логин (жёсткие правила)
Видимое окно WebView2 на `https://soundcloud.com/signin` с постоянным `data_directory` (`login-profile`, не удалять). Без подмены UA, без JS-инъекций, без автозаполнения, без headless. Капчу DataDome решает пользователь; детектим `captcha-delivery.com` и показываем подсказку. Токен — из cookie `oauth_token`, проверка `/me`, хранение в Windows Credential Manager. Разлогин только при 401 на `/me`. Прокси в WebView — `--proxy-server`; SOCKS5/HTTP с логином — через локальный форвардер на `127.0.0.1`.
**Запрещено:** сервисы решения капчи, автоматизация логина, эмуляция TLS-отпечатков браузера (`wreq`/`sc-fingerprint` и аналоги), обход DPI, DoH.

## Производительность
- Закрытие в трей = **уничтожение** главного окна и WebView (не hide); музыка играет из Rust; открытие пересоздаёт окно и восстанавливает экран из состояния Rust. Цель: трей ≤ 70 МБ, открыто на главной ≤ 350 МБ (процесс + `msedgewebview2.exe`).
- Позиция плеера, прогресс, волна — **вне React-стейта**: подписка в листовом компоненте, `requestAnimationFrame`/canvas, таймкоды через `useSyncExternalStore` с флором до секунды. Никаких полей позиции в контекстах/сторах, от которых зависит экран.
- Длинные списки — только виртуализированные. `<img loading="lazy" decoding="async">`. Без blur/backdrop-filter на больших площадях.

## Дизайн
Эталон — `docs/design/mockup.html`. Только CSS-переменные (токены) — никаких хардкод-цветов в компонентах. Акцент `#FF5500`, градиент `#FF7A2F → #FF3D00`, светлая и тёмная темы.

## Безопасность и секреты
Токен и пароль прокси — только Credential Manager; никогда в логах, файлах настроек, событиях к фронту. Логи проходят через `redact()` (`app/log_sink.rs`).

## Проверки
- Rust: `cargo check`, `cargo clippy --all-targets -- -D warnings`, `cargo test` (из `src-tauri/`).
- Фронт: `pnpm tsc --noEmit`, `pnpm biome check src/`.
- Release-сборка (`pnpm tauri build`) — только в конце фазы.
- Тесты — на чистую логику (парсинг api-v2 по фикстурам, резолв транскодингов, построение прокси-URL). Сетевых тестов нет.

## Правила кода
- Без мёртвого кода «на потом» и закомментированных блоков.
- Новая зависимость — только с причиной; в отчёте фазы одна строка обоснования на каждую.
- Компромиссное решение или фаза заметно больше ожидаемого — спросить, не выбирать молча.
- Только Windows: никаких `cfg(target_os = "linux"/"macos")` веток.
